# 好友联机：服主改地址，朋友不用重新配置

此功能面向 Windows x64、Steam 版《方舟：生存进化》。朋友下载后台生成的一个 `.exe`，双击后自动连接服主的联机网络、获取目标地图，再点击「进入游戏」。创建联机包时可选连接成功后自动打开 Steam。

客户端使用 EasyTier 2.6.4 的免虚拟网卡模式。首次运行会把组件和许可文件展开到当前用户的 `%LOCALAPPDATA%/ArkConnect`，关闭客户端会结束它自己启动的联机进程。不安装系统服务，不创建虚拟网卡，不修改系统 DNS 或路由。

## 服主操作

1. 更新项目后，在项目根目录运行 `pnpm build`，然后启动后台和已接入的主机助手。仅需重新生成客户端时运行 `pnpm run build:connect`。
2. 「主机管理」添加并接入运行后台的这台电脑；本机地址可填 `127.0.0.1`。后台和这台电脑的主机助手需要持续运行。
3. 在「地图管理」安装并启动测试地图。
4. 打开「好友联机」→「查找社区共享节点」，选择运营者允许游戏使用、当前可连接的免费节点。然后「新建联机入口」，选择**实际运行后台的主机**与目标地图，填入节点的连接地址。只由服主配置一次，朋友不用填写。
5. 点击「创建联机包」，填写便于识别的名称，下载生成的 `.exe` 发给朋友。

朋友电脑需有 64 位 Windows 10/11、系统的 .NET Framework 4.8、已登录的 Steam 和相同版本的 ASE。普通账户即可运行；Windows 首次运行可能提示应用来源或联网许可，需要由朋友允许此程序运行和联网。客户端目前没有商业代码签名证书。

朋友保持联机窗口开启，出现「可以进入游戏」后点击进入。Steam 显示的 127.0.0.1 是好友电脑上的转发入口，联机客户端通过 EasyTier 将查询和游戏数据转到游戏主机。游戏密码与模组要求照常生效。服主自己的电脑可直接在本机进入服务器。同一电脑运行好友客户端可能与游戏服务占用相同端口。

## 切换服务器

在同一个联机入口点击「切换地图 / 设置」，选择新地图后保存。新地图可以位于另一台已接入的 Windows 游戏主机。后台会自动安排目标主机的组网地址和游戏端口，朋友每约 5 秒获取一次签名配置，自动切换连接，无需重新下载或输入 IP。实际切换还需要等待主机助手接收配置和组网连通。

已经进入游戏的会话需要退出后重新进服。此功能管理连接目标，游戏存档和人物数据的迁移由地图备份/集群功能处理。

后台所在主机和后台端口是首次联机的固定入口。迁移管理后台本身需要保持旧入口可达，或创建新入口并重新分发联机包。修改引导节点时，先保留至少一个旧节点；等客户端获取到新列表后再移除旧节点。

## 没有公网节点时如何连接

服主在 [EasyTier 共享节点目录](https://uptime.easytier.cn/)选择当前可用的社区节点，在后台设置后，主机和朋友的客户端会使用同一份列表。双方先连接相同的节点，再尝试建立直连；直连失败时可能由共享节点转发。节点是否允许中继、是否免费和允许的用途，以运营者说明为准。

旧文档中的 `public.easytier.cn:11010` 已有失效反馈（[官方仓库 issue #1893](https://github.com/EasyTier/EasyTier/issues/1893)），因此本项目不预填为可用默认节点。共享节点目录也属于外部服务，本次未能验证其公网可用性；需要服主确认至少一个可用入口后，再分发客户端。

- 不需要自己购买公网服务器；社区节点的可用性、转发策略和带宽由运营者决定。
- 共享节点无法连接或双方网络限制较严时，客户端会持续重试。可以在后台改为其他可用的 EasyTier 共享节点。
- 当前已完成本机完整 TCP/UDP、控制配置、跨两个独立主机助手的迁移验证。**朋友实际宽带/校园网/运营商之间的连通率、延迟和真实 ASE 进服仍需实测。**本地验收使用自有临时引导节点，不代表默认公网节点已验证可用。

资料：[EasyTier 官方项目](https://github.com/EasyTier/EasyTier)、[社区文档：快速组网](https://doc.easytier.cn/guide/network/fast-networking.html)、[官方配置选项](https://www.easytier.cn/guide/network/configurations.html)。

## 凭据与停用

联机包包含该入口的网络凭据和独立的只读取址凭据，只发给受信任的朋友。客户端使用内置公钥核验后台 RSA-SHA256 签名，拒绝篡改、过期和会话内回退的配置。后台的网络密钥、签名私钥和联机包令牌使用项目既有的 AES-GCM 加密存储。

「停用」后，标准客户端在下一次取址时停止游戏转发并退出组网；「暂停入口」关闭游戏通道，恢复开放后客户端自动重连。配置连续两分钟无法刷新时，客户端会关闭游戏通道，保留自动重试。

各联机包共享同一入口的网络密钥。停用单个联机包会撤销其取址令牌，不能作为对自行改写客户端者的独立网络隔离。需要彻底更换已经分发的网络凭据时，删除旧入口并创建新入口、重新分发联机包。真实游戏访问同时使用地图的服务器密码及游戏权限。

游戏主机只在联机网络中开放所选地图的游戏 UDP、相邻 UDP 和查询 UDP；后台所在主机额外允许后台的 TCP 端口，管理接口继续要求管理员登录。RCON 凭据不会分发给朋友。客户端绑定回环地址，不向朋友本机的外部网卡公开转发端口。

## 构建、文件和排错

- 源码：`native/ArkConnect/*.cs`；不需要 ArkApi SDK。
- 官方未修改组件：`native/ArkConnect/vendor/easytier-windows-x86_64-v2.6.4.zip`。构建和运行前校验固定 SHA-256；缺失时构建脚本尝试从官方 GitHub 续传下载。
- `native/ArkConnect/dist/ArkConnect.exe` 是供后台生成专属包的基础程序。**给朋友的文件请从后台下载**，基础程序没有入口配置。
- 默认路径以 `apps/api` 为工作目录；特殊部署可用 `CONNECT_LAUNCHER_PATH` 和 `CONNECT_VENDOR_DIR` 指定绝对路径。
- Windows 主机助手收到联机设置后，会从已认证的后台接口取得组件并校验。首次准备组件不会阻塞游戏管理的心跳和任务轮询。
- 「等待游戏主机」表示已取得后台提供的地址，当前联机路由还没有到达目标主机。检查目标主机的组网状态。
- 「等待 Steam 查询」表示后台已报告地图运行，客户端还未通过联机转发收到 Steam 查询回包。可先在游戏主机的 Steam 游戏服务器收藏夹中查询同一端口，以区分游戏服务和联机转发。
- 「本机游戏端口被占用」通常是打开了重复客户端，或在服主本机运行。关闭重复程序后重新打开。
- 「签名/配置过期」先检查 Windows 时间是否正确；后台迁移或换密钥后需重新发包。

此版免安装好友联机支持 Windows x64 主机与客户端。原有 Linux 游戏管理能力保留，Linux 联机运行时未随本版实现。
