# 服务端文件管理

同一台游戏主机上，同一 Steam 分支的一套 ASE 专用服务端，可以同时供多张地图使用。例如，两张孤岛可以共用地图资源，分别使用自己的服名、倍率、密码、存档和端口。第一次「准备服务端」才需要下载；再开同分支地图时默认直接关联已有文件，不复制整套程序和地图资源。

以主机助手工作目录 `D:\ArkHost` 为例：

```text
D:\ArkHost\maps\<文件ID>                            Steam 下载的服务端程序和公共地图资源
D:\ArkHost\instances\<地图ID>                       此地图的独立运行目录，包含公共文件引用
D:\ArkHost\instances\<地图ID>\ShooterGame\Saved       本地图的配置、存档和日志
D:\ArkHost\recycle\<地图ID>-<删除任务ID>\Saved        已删除地图的存档和配置
D:\ArkHost\recycle\<地图ID>-<删除任务ID>\runtime      此地图的本地插件、模组等其他运行数据
```

`maps` 和 `instances` 由助手在同一工作目录下创建。Windows 使用本地 NTFS 工作目录。不要手动复制或修改实例里指向公共文件的路径。Workshop 模组自动更新时用各实例自己的目录；ArkApi、ArkShop 等插件也在各实例内单独安装和配置。

ASE 在运行目录下读写 `ShooterGame/Saved`（见 [ASE 服务端配置](https://ark.wiki.gg/wiki/Server_configuration#Configuration_Files)）。因此每个实例都有独立运行目录；Windows 用[硬链接和目录连接](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)访问公共文件，即使在实例目录中看到文件名，也不会占用另一份完整安装的空间。

## 新建、维护与删除

1. 新建地图时选择 Steam 分支和主机。保留「自动共用本机同分支文件，没有时下载」，或从下拉框选择具体文件包。文件已被其他地图使用时也能选择。
2. 点击「准备服务端」，完成后点击「启动」。同一文件包可同时运行多张地图，每张地图仍需要自己的端口、进程和内存。
3. 更新公共文件时，先关闭所有共用地图，再到其中一张的「更新服务端」。助手为每张有存档的地图分别备份，然后只更新一次公共文件。若所有相关地图都启用了自动分支更新，自动维护会合并共用文件及互通组的范围，完成停服、更新和恢复。公开分支与 preaquatica 分支分开存放，不混用。
4. 删除地图会回收它自己的数据并解除文件关联，其他地图可以继续运行。即使最后一张地图删除，公共文件也继续保留。确实要释放下载文件占用的磁盘空间时，在「服务端文件」单独删除；已关联或被未安装地图预留的文件无法删除。

「服务端文件」页面在电脑和手机浏览器都能使用，显示名称、所属主机、路径、大小、版本、最近校验时间和所有关联地图。可以扫描、重命名、复制路径、打开位置、下载、导入和校验。只有明确选择「创建本机副本」才会另建一套独立程序和公共资源。对空闲文件也可以直接校验和更新。下载或复制中断后可从文件任务重试。

「打开文件位置」在保存文件的游戏电脑执行。助手以系统服务运行时可能没有可见桌面；可以复制路径后在游戏电脑手动打开。Linux 可复制路径。导入外部已有服务端会把文件复制到管理目录一次，保留原目录及存档；后续开地图共用导入的文件。未知分支要先选择分支校验。Steam 游戏客户端不是专用服务端。

## 升级旧部署

保留原来的 `.env`、`.data`、助手配置和工作目录。在管理电脑和游戏电脑分别替换源码，执行 `pnpm build` 并重启后台和主机助手。已有地图建议先正常停服。新版扫描会把已停服的旧安装移动到 `maps`，配置、存档和插件数据仍留在对应实例；旧版文件库 `server-files` 的已下载文件也会移入 `maps`。迁移使用同盘移动，运行中的旧地图不会被自动停服，停服后可点「扫描主机文件」。旧版本已有的多份下载不会擅自合并或删除。

反向代理需转发 `X-Ark-Agent-Features` 请求头。旧助手不会领取需要共享文件支持的安装、更新和删除任务；升级后继续。
