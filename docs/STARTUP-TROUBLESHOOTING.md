# 地图启动反馈与排错

地图列表会显示启动阶段、已等待时间、进程 PID、RCON 检测结果及最近两条启动日志。点击「查看启动日志」进入地图详情，可查看最近十条日志、最后检测时间、最后日志时间及游戏电脑上的完整日志路径。

## 如何判断结果

- **检查配置 / 创建进程**：助手正在准备配置并创建游戏进程。
- **等待地图就绪**：进程存在，但 RCON 尚未响应。地图、存档、模组及磁盘性能会影响等待时间；没有真实加载百分比时，只显示等待指示和实际耗时。
- **启动检测通过**：本机 RCON 已成功验证并响应查询，可以尝试进服。这不代表朋友的网络、共享节点或公网端口也已验证。
- **启动检测失败**：进程提前退出、创建失败，或超过 30 分钟仍未就绪。提前退出时保留能取得的退出码和最后日志；超时时保留进程供检查，不重复创建进程，也不标成运行成功。
- **主机反馈已中断**：页面保留最后信息并提示结果待确认，请先检查主机助手连接。

启动过程会持续更新任务进度，并通过助手心跳向后台上报最近状态；网页约每五秒刷新。助手在启动期间重启，会保留原来的等待起点并重新核对 RCON，不会仅凭进程存在就认定启动成功。

新的启动请求会清除上一次的启动结果。超时后仍有进程时，自动拉起不会再次提交启动任务，避免覆盖原始故障信息。

## 启动日志

查看运行游戏的那台电脑上、该地图独立目录中的：

```text
<主机助手工作目录>/instances/<地图ID>/ShooterGame/Saved/Logs/ArkControlProcess.log
<主机助手工作目录>/instances/<地图ID>/ShooterGame/Saved/Logs/ShooterGame.log
```

前者记录进程的标准输出和错误输出，后者由游戏写入。后台展示有界的最近日志，并隐藏已知的入服密码与 RCON 管理密码。完整文件保留在游戏电脑上。读取从本次启动开始，处理日志轮换及分批写入的中文；助手恢复后也会读取现有文件的末尾以便排错。

如果等待较久，查看 PID、CPU/内存、日志是否仍在更新，以及最后一次 RCON 检测错误。没有新日志并不能单独证明进程卡死；RCON 未响应也不能单独证明游戏已经退出。启动失败且仍有进程时，可先尝试关闭；无法正常退出时再使用已有的强制关闭入口。

### 超过 30 分钟、进程仍在但没有日志

启动检测是在**运行游戏的电脑**上访问 `127.0.0.1:<RCON端口>`。这一步无需公网节点、端口转发或好友客户端，先检查本机进程和 RCON，不要为了排错公开 RCON，也无需关闭整台电脑的防火墙。

新版页面在超时后仍显示「最后一次 RCON 检测错误」，失败任务也保留这个原因：

- `ECONNREFUSED`：本机连接被拒绝，检查 RCON 是否开始监听以及配置是否生效。
- TCP 已连接但未收到密码验证结果：有程序接受连接，但没有完成预期 RCON 认证，需检查端口对应进程及程序状态。
- 密码验证失败：游戏使用的管理密码与助手凭据不一致；不要公开密码或随意改成空密码。
- 密码验证通过但未收到命令响应：认证成功，游戏未及时处理查询，不等同于未创建进程。

助手在启动前写入 `[ServerSettings]` 下的 `RCONEnabled=True`、分配的 `RCONPort` 和后台保存的管理员密码。本次兼容修正同时在启动 URL 传入这三项，避免只写入 INI 的密码没有被游戏采用。这里使用原有后台凭据，不生成另一套密码，不需要手动改数据库或加密密钥。这种启动方式与 [CubeCoders 的 ASE 启动模板](https://github.com/CubeCoders/AMPTemplates/blob/main/ark-seminapi.kvp) 一致，但不能仅据模板判断用户具体机器的故障原因。

密码会出现在游戏电脑的本地进程参数中，游戏生成的原始日志也可能包含参数。上传至后台的进度、错误、进程日志和部落推送会脱敏；进程输出文件以限制性权限创建，Windows 上还取决于目录 ACL。不要公开完整进程命令或未经检查的原始日志。

若游戏进程只有游戏/查询 UDP 端口、没有对应 TCP RCON 监听，优先核对 RCON 开关、管理员密码来源、配置实际路径及端口；仅有 UDP 端口不能证明 RCON 已启用，也不能证明玩家已经进服。启动参数修正需在**重新启动地图进程后**生效，单独重启助手不会改变现有游戏进程的参数。无法通过 RCON 正常停服时，先确认无须保留未保存进度，再使用后台的强制关闭，避免直接结束未知进程。

可在游戏电脑的项目根目录打开 PowerShell，运行下面的只读诊断。将 `16816` 替换为地图详情当前显示的 PID：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\diagnose-startup.ps1 -GamePid 16816
```

脚本按该进程的程序路径定位地图目录，显示内存、两秒内 CPU 使用量、RCON 配置是否存在、TCP 监听的实际进程、UDP 端口，以及两份日志的路径、大小、更新时间和末尾内容。新增 `IniAdminPasswordConfigured` 明确表示 INI 是否有管理员密码；有权限读取进程选项时，`LaunchOptions.AdminPasswordProvided` 表示启动参数是否提供密码，只显示布尔值，不显示密码或完整命令。无法读取进程选项时 `Readable=false`，不能据此认为未传密码。`Responding` 是 Windows 进程属性，不作为地图就绪判断。脚本不结束进程、不修改配置、不发网络请求；日志会对常见凭据字段及已读取的游戏密码脱敏，分享前仍请检查内容。

如果 PID 已退出，先以地图详情刷新后的 PID 为准。读取路径或端口权限不足时，请用运行助手的同一用户执行，必要时以管理员身份打开 PowerShell。将诊断输出及最后一次 RCON 错误提供给维护人员，才能区分游戏未完成初始化、配置/端口问题与启动检测问题。无需删除地图、清空下载文件或把等待时间继续延长来收集这些信息。

当前启动检测以主机本地的 RCON 实际响应为依据，没有把日志中的 “ready” 文本当作成功标志，也没有确认真实玩家已进入地图。

## 更新

本次 RCON 修正主要位于游戏电脑的主机助手。在原项目目录覆盖源码，保留 `.env`、`.data` 和主机配置，然后执行：

```powershell
pnpm install
pnpm --filter @ark-control/agent build
```

关闭旧助手，再使用原接入方式启动新助手，通常是 `pnpm agent`。**现有游戏进程也必须先停止再启动**，不需要删除地图或重新下载游戏。RCON 当前不可用时普通停服可能失败；强制关闭会失去未保存的进度，应由管理员确认后操作。

保留原 `.env`、`.data` 和游戏目录，更新后执行 `pnpm build`，重启后台及游戏机器的助手。只刷新网页无法让旧助手上报新增的启动阶段和日志。

本地验收使用 Windows 测试进程延迟开放 RCON、输出启动日志并模拟退出码 42；真实 ASE 的具体启动耗时及玩家进服仍需实机验证。
