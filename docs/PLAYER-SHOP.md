# 版本、用户与游戏商店

商店按互通组选择一种模式。ArkShop 模式使用原插件处理 `/shop`、`/points` 和 `/buy`。独立模式由平台管理商品、金币、VIP 和订单，Windows ASE 游戏服通过独立插件处理 `/as` 指令。两种模式使用各自保存的余额与 VIP。存量互通组默认使用 ArkShop。

## 使用独立商店

1. 更新管理后台和游戏主机助手。在「商店管理」选择互通组，停止组内地图后切换为「独立商店」。
2. 在「商店管理」点击「安装依赖」。导入与地图分支匹配的 ASE ArkApi ZIP，选择目标地图并安装后台自带的独立商店插件。如果地图装过 ArkShop，先备份并将旧插件目录移出 `ArkApi\Plugins`，再提交安装。详见 [安装与构建](../native/ArkControlShop/README.md)。
3. 在「商店管理」添加商品。可设置普通价、VIP 价、上架状态和按 SteamID64 累计的限购。保存后组内生效；换地图会继续使用同一份额度。物品支持蓝图、数量、品质和可用的护甲、耐久、武器伤害属性。驯服恐龙一次发放一只。实际属性由游戏和蓝图的属性范围决定。
4. 在「用户管理」按 SteamID64 发放金币及限时 VIP，离线也可操作。VIP 价格面向任何有效的独立商店 VIP。购买仅使用游戏金币。
5. 玩家在游戏聊天框输入 `/as shop [页码]` 看商品、`/as points` 查金币、`/as buy 商品编号 [数量]` 下单。购买数量默认为 1。同组余额和限购由管理端统一结算，每单发到玩家下单时所在地图。

下单和扣款一起落库。明确未发货的回执会退还金币和限购额度。部分或未知结果进入「商店管理 → 独立商店订单」，核对后可确认发货或确认完全未发货并退币。管理员的核实结论保存在消费流水。切换回 ArkShop 后仍可查看以往的独立商店订单。

## 更新项目

管理后台和各游戏电脑的主机助手需要一起更新到本版，并在各自项目中执行 `pnpm install`、`pnpm build` 后重新启动。已有 `.env`、主机凭据及 `.data` 应保留。管理后台和主机助手可以位于不同电脑。

## Steam 分支

新建地图选择「公开分支」或「preaquatica」。这是分支选择：公开分支对应用户当前使用的 361 系列及后续公开更新，preaquatica 对应 358 兼容分支及该分支后续更新。界面没有锁定某个小版本。

- 下载/更新均明确向 SteamCMD 传入 `-beta public` 或 `-beta preaquatica`，避免上一次 beta 选择影响下一张地图。
- 文件库记录分支；自动复用与指定复用只允许相同分支。旧目录无法判断分支时显示 `unknown`，先在文件库选择分支并校验/修复。
- 同一互通组的地图必须选择相同分支。已安装地图不允许直接改变分支，避免把已有存档直接交给另一版本读取。
- 新建地图默认开启自动跟随分支，旧地图默认保持关闭。互通组全部地图均开启、主机在线且没有待处理管理任务时，才会自动整组维护。
- 助手每 15 分钟查询 Steam **服务端**分支 BuildID；它不要求客户端与服务端 BuildID 数字相等。
- 检测到更新后，全组先进行 60 秒停服倒计时，全部停止后逐图备份和更新。确认全组 BuildID 一致后，只恢复此前运行的地图。
- 任何阶段失败都会暂停后续步骤。用户管理中的「分支更新」查看原因并手动重试；不会因重复检测同一 BuildID 不断重试。

自动更新依赖 Steam 连通性和该分支实际可用的服务端、模组及插件。游戏内容和 SDK 的真实版本兼容需要在测试服验证。

## 用户档案与筛选

「用户管理」选择一个互通组。无互通组的地图显示为各自的独立服。

同组内以 SteamID64 合并用户，记录名称历史、最近出现、当前在线地图、采样累计在线时间、备注、可采集的部落、IP、客户端设备、金币与本后台发放的 VIP。不同组的档案和经济分开保存。现有地图详情中的玩家列表仍保留。

地图运行且 RCON 就绪后，助手约每 30 秒自动采样。超过 60 秒没有新采样会显示离线。在线时间是采样估计，不是精确计费时长。可手动添加 SteamID，插件通常要求玩家至少进服一次、已经建立游戏数据库记录后才能变更其余额或权限。

普通 RCON `ListPlayers` 只提供玩家名和 SteamID。没有游戏桥接时，IP、部落和设备字段允许为空，不会填造数据，也不会把管理 API 的请求 IP 当成玩家真实 IP。

## 安装服务端插件

此功能面向使用最新版主机助手的 **Windows ASE 游戏主机**。在「地图管理 → 服务端插件」选择互通组或独立服。页面默认勾选可安装的地图，可以逐张取消。安装需要先停止要操作的地图。

ArkShop 模式需要以下三个组件。按地图的 Steam 分支导入官方下载的 ZIP，选择目标地图后提交安装。

1. [ASE ArkApi](https://forum.ark-server-api.com/resources/ase-server-api.32/)
2. [ASE Permissions](https://forum.ark-server-api.com/resources/ase-permissions.35/)
3. [ASE ArkShop](https://forum.ark-server-api.com/resources/ase-arkshop.36/)

每张地图显示自己的任务进度、错误和插件状态。写入文件后，启动地图才能检查 DLL 是否加载。新安装会保留原有插件和配置。碰到同名配置时，会另存一份到该地图的 `Win64\ArkControlPluginBackups\<任务ID>`。插件位于各地图的专有目录。

```text
<主机工作目录>\instances\<地图ID>\ShooterGame\Binaries\Win64\ArkApi\Plugins\
  ArkShop\config.json
  Permissions\config.json
```

管理端的 MySQL 用于本项目。游戏插件数据库是另一套配置，不能因为本项目数据库能运行就认为该 MySQL 版本也受插件支持。请按实际下载的插件说明选择兼容数据库。

同一互通组的多张地图，ArkShop 应使用同一个共享 MySQL 玩家库，Permissions 也应指向该组共享的权限库；不同互通组应使用不同玩家库/表。后台读取各地图配置后检查连接目标的一致性；跨电脑的 `localhost` 不会被当成同一数据库。同一电脑的 localhost 连接会结合主机标识判别。该检查是配置核对，不能替代一次真实跨图余额与权限测试。

复用服务端目录时，不复制 ArkShop / Permissions 的本地 SQLite 数据文件、旧日志和地图 Saved，避免把旧玩家数据带到新图。MySQL 连接配置仍需管理员按互通组核对。

## ArkShop 模式的金币与 VIP

先在「商店管理」读取主机配置。多地图组需读到组内全部地图的配置；配置目标不一致或仍使用独立 SQLite 时，不允许把它们作为共享经济发放。

金币操作以 ArkShop 为准：读取余额、调用 `ChangePoints` 增减、再读取余额。后台没有另建一个与游戏不同步的钱包，不会用旧余额直接覆盖游戏中的并发消费。金额是这次已请求的变化量；前后余额是采样值，多地图并发交易时不能只用两次余额差推断这笔业务。

VIP 设置填已有的 Permissions 组名，默认为 `VIP`。实际商品优惠、定时积分和礼包权限需要在对应插件中配置。后台通过 `Permissions.AddTimed` 发放/续期，通过 `Permissions.RemoveTimed` 撤销本后台管理的限时组，不会授予管理员组。时长单位为小时，续期按本后台记录的未到期时间累加并取整。外部直接修改的到期时间不一定能通过普通 RCON 读回，操作前应核对原权限。

每个操作先落库，再由助手领取。助手在非幂等操作前写本地执行记录。断线、超时或进程中断后的不确定结果显示为「结果未知」，不会自动再发一次。管理员先核对游戏余额、权限和日志，再填写核实依据。核实按钮只登记结论，不发放金币。

## ArkShop 模式的配置编辑

采用后台原生页面，无需 iframe 或第三方网页商店。

1. 读取各地图现有 `ArkShop/config.json`。
2. 再次读取不会覆盖已有草稿，可点击对应地图的「载入此配置到草稿」显式载入。
3. 在「商品 / 礼包 / 回收」编辑 ID、描述、价格和发放定义。物品蓝图、恐龙、指令、权限和其他插件字段可以在 JSON 中编辑。
4. 保存草稿；多人/多窗口修改会检查草稿版本。
5. 发布到组内地图。每张地图先备份原文件、核对文件哈希，再写入配置；运行中的地图执行 `ArkShop.Reload`，停服地图在下次加载插件时生效。
6. 每张地图单独显示结果，写入文件和重载结果分开记录。外部改过配置时先重新读取合并。配置发布不支持跨多台电脑的一次原子提交。

数据库和 Discord 通知凭据保留在游戏主机；网页草稿和导出不包含它们。备份位于主机工作目录的 `shop-backups`，包含原配置凭据，应按主机配置备份管理。JSON 校验检查结构、ID、价格与等级范围，物品蓝图/指令是否在对应游戏版本有效还需真实进服检查。

ArkShop 模式的消费由 ArkShop 在游戏内完成。礼包次数、定时奖励、会员价格和商品权限按已安装 ArkShop 的能力配置。

## 流水覆盖范围

后台发起的金币、VIP、封禁和配置操作全部保存任务编号、所属服、SteamID、原因、时间、执行状态与回执。最近页默认显示 200 条；「导出本组完整流水」通过分页导出该组已保存的全部记录。

游戏内记录有两条输入：

- ArkShop 自己生成的商店日志：保留原文。无法从原文确认的扣币金额、商品数量和发货结果不作推断。
- 结构化桥接 JSONL：可保存明确的金额、商品与事件编号，按地图及事件编号去重。协议见下文。

只轮询余额无法得到完整消费历史。在线奖励、其他插件直接改库等未写日志的变化，普通 ArkShop 商店日志未必覆盖。可选的 [ArkShop 源码审计接入](../native/ArkShopAudit/README.md) 为 `AddPoints`、`SpendPoints`、`SetPoints` 的已知成功路径输出结构化记录；它需要相应 ArkShop 源码及 ASE SDK 编译。本源码包没有冒充已编译且在真实游戏验证过的 DLL。

游戏审计记录和后台操作记录可能同时描述同一业务的不同层次；它们的来源不同，不能简单相加当作重复发币。其他插件绕过 Points API 直接写数据库仍需要对应插件的事件接入。文件日志与游戏数据库不是一个事务，异常断电/磁盘错误时仍需核对游戏记录。

退款/补发采用管理员核实后调整金币并在原因中关联原流水，不自动根据模糊日志退款，也不自动重复执行结果未知的交易。

## IP、SteamID 与设备封禁

SteamID 封禁下发至组内每张地图；未运行的地图会等待就绪后执行。任务的每个目标分别显示结果，不能把「已登记」当成全部地图都已封住。

IP 必须来自游戏桥接观察，拒绝回环、EasyTier 固定转发网关等地址。历史上多人共用同 IP 时要求管理员确认影响。Windows 助手通过防火墙仅封禁相应地图的游戏 UDP 端口，需要相应主机权限；权限不足显示失败。删除地图时清理助手登记的规则，普通停服保留封禁以便下次启动继续生效。

设备标识通过「好友联机 → 创建联机包 → 绑定 SteamID64」启用。首次图形界面运行说明用途并请求同意；读取 Windows 安装标识，按所属服哈希后发送，不发送原值、不采集 MAC/磁盘序列号，不将转发 API 地址当作玩家公网 IP。管理员填入的 SteamID 关联不等于已经验证 Steam 登录。

封禁后，遵守协议的联机客户端会关闭游戏转发，解封后继续检查。普通 Steam 直连仍允许；设备标识可能被重装、伪造或换客户端绕过，不是强制反作弊。旧的未绑定联机包不具备设备覆盖能力。到期后客户端规则失效，Steam/IP 的解封仍需要游戏主机完成回执。

## IP/部落观察桥接

[ArkTribeBridge 源码](../native/ArkTribeBridge/README.md) 在部落日志之外，增加每约 10 秒输出 `ShooterGame/Saved/Logs/ArkControlPlayers.json` 的玩家 SteamID、名称和游戏观察 IP。SDK 与 358 / 361 真实兼容性需要分别编译、测试；本环境未编译该 C++ DLL。

可接入自有适配器，玩家快照格式：

```json
{
  "sampledAt": "2026-11-05T00:00:00.000Z",
  "players": [
    {
      "steamId": "76561198000000001",
      "name": "玩家",
      "ip": "198.51.100.10",
      "tribeId": "123",
      "tribeName": "部落"
    }
  ]
}
```

消费事件文件 `ShooterGame/Saved/Logs/ArkControlCommerce.jsonl` 每行一个对象：

```json
{
  "eventId": "本地图内永久唯一的事件ID",
  "steamId": "76561198000000001",
  "kind": "shop-purchase",
  "occurredAt": "2026-11-05T00:00:00.000Z",
  "detail": { "productId": "stone", "quantity": 2, "amount": 20, "status": "delivered" }
}
```

时间使用带时区的 ISO 时间。助手按完整换行读取，保留文件游标，后台按地图和事件 ID 去重。事件 ID 不要随重传改变，不能复用。只有已验证主机凭据可以上报其所属地图的数据。
