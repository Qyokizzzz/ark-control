# 验证方法与上线边界

## 日常检查

```sh
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

纯规则测试不依赖游戏、QQ 或数据库，验证消息模板、归一化边界、部落来源识别、游标恢复、UTF8 分片、长日志完整性、资源估计、端口、路径与 RCON 数据包。安装向导测试还覆盖提示立即显示、批量输入、密码不回显、输入结束与取消，以及环境配置原样保存。

## 完整本地联调

当前联调还覆盖公开/preaquatica 分支隔离、同组用户合并及跨服隔离、金币幂等和未知结果、VIP、消费游标、配置脱敏与备份、发布冲突、客户端设备封禁，以及组内「全部停服 → 全部更新 → 恢复原运行地图」状态机。Windows 防火墙命令使用替身测试，不会在开发机添加真实封禁规则；游戏插件响应仍为本地替身，C++ 桥接 DLL 仍需实服构建和验收。

如只排查本次用户/商店和分支流程，可以在 PowerShell 设置 `$env:ARK_VERIFY_ONLY_MANAGEMENT='1'` 后执行 `pnpm test:e2e`；报告会明确标记 `partial: true`，不能代替完整交付回归。恢复完整模式先执行 `Remove-Item Env:ARK_VERIFY_ONLY_MANAGEMENT`。本地生成的 `.data` 为验证材料，不进入源码包。

Windows 环境运行 `pnpm test:e2e`。需要 Node / pnpm、`mysqld.exe`、系统 .NET Framework 的 `csc.exe` 和 Edge。MySQL 不在 PATH 时，先设置环境变量 `MYSQLD_BIN` 为程序的绝对路径；浏览器可用 `BROWSER_BIN` 指定。

验收器在项目 `.data/verification/时间戳` 创建独立数据库目录，随机分配端口并生成临时管理员。不会连接已有游戏服务器，也不会接触已有 MySQL 数据目录。QQ 请求发往本地 HTTP 替身。测试使用独立 C# 进程模拟游戏的 RCON、保存和退出行为，不代表真实 ASE 已验证。

验收覆盖：

- MySQL 建表、管理员登录、未授权访问、刷新令牌轮换和重放撤销。
- 一次性主机接入码、主机独立认证、端口冲突和配置部分更新。
- 默认与客户机器人隔离、密钥加密存储、群与机器人归属检查。
- QQ HTTPS 回调地址挑战、官方 Ed25519 签名向量、原始字节验签、防篡改与超时拒绝、一次性群绑定。
- 游戏替身实际进程启停、RCON 就绪、玩家列表、停服倒计时取消。
- SteamCMD 替身验证独立初始化、登录前指定安装目录及安装前刷新应用信息；退出 7、明确的退出 8 Missing configuration 均仅重试一次。持续失败时回传应用与连接日志，再次成功后清除地图旧错误；浏览器任务页保留错误换行。
- 地图列表和详情的启动/重启、关闭、重新安装及删除；检查实际 Windows 旧进程退出、RCON 端口释放、CPU/内存归零、存档回收、删除后的端口复用、关联计划/订阅/联机凭据清理。主机断开取消倒计时任务并关闭全部游戏与联机组件；重新接入后清理地图、断开和删除主机，旧令牌及接入码失效，迟到心跳不恢复在线。见 `scripts/verify-lifecycle.mjs`。
- 助手重启后接管同一游戏进程，不重复启动。
- 延迟开放 RCON 时，地图保持启动中并持续上报时长、PID、真实启动日志；桌面及手机可查看，无虚构百分比。实际响应后才确认启动检测通过；提前退出保留退出码及最后日志，并清空资源上报。单元测试还验证启动期间助手重启后的就绪复核及超时不会被误报为运行成功。
- 旧数据库自动补齐状态、到期字段及索引，原有 JSON 记录保留。复现缺失字段导致的轮询 500，核对错误编号、实际 SQL 原因及脱敏日志，再验证升级后同一助手自动恢复。
- 未接入主机上的新地图可直接删除；离线已安装但未运行地图立即移出列表，保留存档及持久化收尾任务，助手重连后回收存档并保留下载文件。验证重复删除幂等、有待处理任务时不能删除主机，以及卡住的断开请求可重新连接。
- 文件库迁移旧目录；两个孤岛同时以独立 Windows 进程启动，核对公共文件身份、独立配置和 RCON 端口，并确认没有额外下载。在线时拒绝更新，全部停服后分别备份、一次更新。删一张图后另一张继续运行，最后一张图删掉仍保留文件包。外部导入、下载重试、显式文件删除及旧助手能力拦截也在 `scripts/verify-server-files.mjs` 验证。
- 从旧路径迁移助手配置，保留原游戏目录、互通目录和 HTTP 授权；更换工作目录后重启仍使用同一配置，临时 500 后自动重试。地图与联机密钥损坏时显示对应告警，主机继续心跳，未运行地图仍可删除。见 `scripts/verify-reconnect.mjs`。
- 备份压缩、传输校验、授权下载、恢复前备份和存档恢复。
- 精确部落分流、跨主机事件拒绝、重复上报不加计数。
- 首条到达后固定 30 秒合并，后台重启保持截止时间与计数，两台机器人分别发送。
- 浏览器登录与各个页面、五主题切换及 390px 手机宽度。
- 好友专属客户端生成、只读令牌隔离、RSA-SHA256 配置签名。
- 真实 EasyTier 免网卡模式，游戏、相邻与查询 UDP 端口双向通信；临时引导节点仅用于本地测试。
- 同一客户端热更新到第二个独立主机助手，暂停/恢复入口、停用联机包和进程清理。
- 游戏主机助手重启后，核对专用运行时路径、清理记录的旧组网进程，好友客户端恢复连接。
- 浏览器创建、更新、删除联机入口，实际下载专属 EXE，桌面与手机联机页面。

成功生成 `report.json` 及总览、地图、主机、启动状态、文件库与好友联机的桌面/手机截图；失败时保存诊断日志和浏览器截图。文件库的“打开文件位置”由单元测试替换进程调用验证，不会打开当前电脑的资源管理器；复制路径的浏览器测试使用临时剪贴板替身。真实游戏主机的可见桌面与系统剪贴板还需实际使用确认。测试结束会停止本次创建的进程，保留验收目录便于排查。目录包含较大的临时 MySQL 数据，应在检查完报告并确认测试进程已退出后清理。

## 真实接入时仍需验收

1. 通过 SteamCMD 安装真实 ASE 服务端，检查运行库、真实地图、模组加载与玩家连接。
2. 在实际 ASE / ArkApi SDK 编译插件并逐项触发部落日志，核对部落 ID、中文与正文。此交付没有已编译 DLL，也没有以模拟结果代替游戏内验收。
3. 使用真实 QQ 机器人完成凭据验证、事件连接、群绑定和测试发送。腾讯权限、主动消息、白名单和配额以该账号实际结果为准。
4. 用真实存档做一次停服备份及恢复；互通目录单独备份。跨主机互通要验证共享存储。
5. Linux 助手源码与类型检查已覆盖，当前完整进程验收在 Windows 运行。Linux 的 SteamCMD、游戏和日志来源还需要 Linux 主机验证；Windows ArkApi DLL 无法直接复用。
6. 好友联机需在朋友的真实网络中验证共享节点、打洞/中继、延迟、Steam 拉起和真实 ASE 进服。当前新增的免安装联机功能仅支持 Windows x64。详见 [好友联机说明](FRIEND-CONNECT.md)。

日志原文不会为了适配 QQ 被静默截断。平台拒绝过长内容时保留原始事件并显示失败原因，由管理员处理。首版管理页面展示最近记录，完整事件仍保存在数据库；单 API 工作进程及串行写事务的吞吐量应在实际订阅规模下压测。
